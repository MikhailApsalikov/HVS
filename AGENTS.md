# Работа над Hunters versus Spiders

- Обсуждайте с владельцем игровые правила, а не детали кода, если он не просит обратного.
- `src/domain/rules/numbers.ts` — единственная формула бонусов. Порядок: положительные линейные → положительные проценты → отрицательные проценты → отрицательные линейные → округление.
- Один талант даёт один бонус текущей силы (ранг 2 по 10% = 20%). Разные таланты и разные предметы — независимые источники. Все модификации предметов активны.
- Базы, рост за уровень и точность параметров находятся в `rules/stats.ts`, контент — в `src/content`. Первичные характеристики рассчитываются до производных; их вклад и броня определены в `rules/attributes.ts`. Не дублируйте значения или формулы в UI.
- Ядро не импортирует UI, инфраструктуру или браузерные API. Интерфейс отправляет команды и читает состояние. Время и случайность в тестах управляются явно.
- Любое изменение игрового поведения сопровождается юнит-тестом через публичный API сессии; ошибка — регрессионным тестом. В проекте используются только юнит-тесты, без Playwright и браузерных тестов. Миграция сохранения требует теста предыдущей версии.
- Перед завершением запускайте `pnpm check` (типы, форматирование, юнит-тесты, покрытие и сборка). Не снижайте пороги покрытия ради прохождения проверки.
- Флаг версии выставляйте до итогового `pnpm check`. Проверка отклоняет изменения игры без нового флага `balance`/`cosmetic` в рабочем дереве или последнем коммите; `none` допустим только без изменений игры. При ошибке проверки AI сам добавляет недостающий флаг, не перекладывая это на владельца. Уже записанные флаги нельзя удалять или менять.
- `documentation/*.txt` — исторические спецификации. Актуальные решения записываются в `docs/rules.md` и исполняемых определениях.
- Не возвращайте `node_modules`, `dist`, покрытие и результаты тестов в Git. Не храните параллельную старую реализацию правил.
- Версия игры — `3.X.Y.Z`: X и Y генерируются автоматически по флагам AI в `game-version.json`; владелец не меняет числа вручную. В конце каждой задачи AI обязан выполнить `pnpm version:flag <balance|cosmetic|none> <уникальный-id-задачи>`: `balance` — изменения игровых правил и баланса, `cosmetic` — внешний вид, звук и интерфейс без изменения баланса, `none` — только инструменты, документация и тесты. Для смешанной задачи выбирается `balance`. Одна задача — один новый ID и один флаг; повтор команды с тем же ID не повышает версию снова. Накопленные записи не удаляются и не переиспользуются. Сборка считает X по флагам `balance`, Y — по `cosmetic`, начиная с 0/0; повышение X не сбрасывает Y. Z автоматически определяется историей Git и растёт с каждым коммитом без AI, не сбрасываясь при изменении X/Y. При завершении задачи укажите выставленный флаг.
