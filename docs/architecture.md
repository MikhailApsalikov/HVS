# Архитектура

## Выбор технологий

TypeScript со строгой проверкой типов, Vite для браузерной сборки, Vitest для правил и интеграций, Playwright для проверки готовой сборки. Версии зависимостей закреплены в pnpm-lock.yaml. У приложения нет серверной части и производственных зависимостей.

Это небольшая двухмерная игра с девятью линиями и существующими SVG. DOM и CSS достаточны для отображения; отдельный графический движок, React и глобальное хранилище состояния добавили бы второй жизненный цикл без пользы для нынешних правил. Если позднее понадобится Canvas/WebGL, меняется представление, а не игровая модель.

Проверены официальные основания выбора: [строгие проверки TypeScript](https://www.typescriptlang.org/tsconfig/strict), [производственная сборка Vite](https://vite.dev/guide/build), [статическая публикация Vite](https://vite.dev/guide/static-deploy.html). Выбор конкретной архитектуры ниже — решение для этого проекта, а не требование этих инструментов.

## Слои

| Каталог                     | Ответственность                                                                                 |
| --------------------------- | ----------------------------------------------------------------------------------------------- |
| `src/content`               | Каталоги предметов, талантов, способностей, пауков и сложности                                  |
| `src/domain/rules`          | Единственная формула бонусов, округление, базовые значения, цены, расчёт итоговых характеристик |
| `src/domain/model`          | Персонаж, ресурсы, инвентарь, таланты, пауки, стрелы, перезарядка                               |
| `src/domain/systems`        | Применение способностей и этапы боя                                                             |
| `src/domain/GameSession.ts` | Команды игрока, последовательность шага симуляции и переходы фаз                                |
| `src/domain/save.ts`        | Версия снимка, проверка входных данных, миграция и восстановление                               |
| `src/application`           | Соединение сессии с сохранениями, событиями и отображением                                      |
| `src/infrastructure`        | Браузерный цикл кадров, клавиатура, аудио, localStorage                                         |
| `src/ui`                    | Отображение и команды пользователя; никаких собственных расчётов бонусов                        |
| `src/bootstrap.ts`          | Единственная точка сборки приложения и освобождения обработчиков                                |

Ядро не обращается к браузеру и хранилищу. `GameSession` можно запускать в Node с управляемым источником случайности. Симуляция делает фиксированные шаги по 1/60 с; цикл ограничивает накопление времени после задержек браузера. Пауза не меняет ресурсы, поле или таймеры.

`GameRules` получает базы и модификаторы с указанием источников. Он возвращает итоговые значения и при необходимости все промежуточные стадии. Инвентарь не изменяет характеристики напрямую: после изменения набора источников весь набор значений пересчитывается заново. Это исключает оставшиеся после продажи бонусы.

События боя (`coinDrop`, `damage`, `absorb`) описывают случившееся, но ничего не знают о звуке, DOM и анимации. Интерфейс читает итоговые характеристики из состояния, а подсказки талантов и предметов строятся из тех же описаний эффектов, которые использует расчёт.

## Как менять игру

- Новый числовой параметр: добавить определение и политику в `rules/stats.ts`, затем эффект в каталог и сценарий поведения.
- Новый талант: описание эффектов в `content/talents.ts`, доступность и предел рангов в конфигурации сложности.
- Новый предмет: данные в `content/items.ts`; преобразование его эффекта в общий модификатор находится в `rules/itemModifiers.ts`.
- Новый тип паука: описание в `content/spiders.ts`; отдельное поведение, если нужно, в `systems/CombatSystem.ts`.
- Новая способность: описание и эффект в каталоге, обработчик в `systems/AbilitySystem.ts`; общий код стоимости и перезарядки остаётся общим.
- Влияние основных характеристик: добавить отдельные правила получения баз производных характеристик. Сейчас такого влияния намеренно нет.
- Новый источник усилений/ослаблений: `Character.setModifiers(source, modifiers)` и `refreshStats()`. Повторная установка заменяет источник; удаление убирает все его эффекты.

При изменении формата сохранения увеличивается версия и добавляется миграция вместе с тестами. Старые непонятные или повреждённые записи не удаляются автоматически.

## Границы переноса

Старые игровые системы и дублирующие подсказки удалены. Визуальные ресурсы, стили и небольшие компоненты отображения сохранены и подключены к новому ядру. Сгенерированные зависимости и сборка убраны из индекса Git и остаются локальными артефактами.
